# Implemented and planned functionality

This page separates what exists (and is tested) from what is only planned. If a feature is not in
the first table it is not implemented. Scope: 2D drafting for architecture and civil work.
Out of scope and removed: 3D modelling and viewing, parametric constraints, and
mechanical-engineering commands (mass properties, ordinate and arc-length dimensions, centre
marks, isometric drafting).

## Implemented

| Area | Functionality |
|---|---|
| Files | Open and save DXF; open and save DWG through a DXF bridge (native builds only); export PDF, SVG, PNG. Flatten on import, `.bak` before the first overwrite ([maintenance.md](maintenance.md)) |
| Drawing | Line, polyline, circle, arc, ellipse, rectangle, polygon, spline, point, construction line, ray, multiline, revision cloud, wipeout, hatch, boundary, region, text, multiline text, blocks and attributes |
| Modify | Move, copy, rotate, scale, mirror, stretch, offset, trim, extend, fillet, chamfer, break, join, explode, lengthen, align, array (rectangular, polar, path), overkill, polyline and spline editing, group, match properties, flatten |
| Dimensions | Linear, aligned, radius, diameter, angular, baseline, continue, quick dimension, multileader, dimension styles, text edit, associativity |
| Layers and properties | Layer manager and layer tools, layer states, linetypes, lineweights, colours, plot styles, text and dimension styles |
| Layouts and output | Paper-space layouts, viewports, page setup, PDF plotting |
| Maintenance | `PURGE`, `AUDIT`, `RECOVER`, `FLATTEN` ([maintenance.md](maintenance.md)) |
| Architecture: layers and rooms | `hcwlayers` (HCW and building-permission layer sets), `room` (room labels with area), `rarea` ([hcw-kit-port.md](hcw-kit-port.md)) |
| Architecture: walls and openings | `wall.draw` (mitred faces and end caps), `wall.door`, `wall.window` (cut the wall lines, place a block that carries a deduction line, link the schedule entry), `wall.clean` |
| Architecture: structure | `grid.axis`, `column.place`, `column.schedule`, `lintel.draw`, `stair.plan` (straight or dogleg, risers, goings, concrete volume), `lift.shaft`, `rail.draw` |
| Architecture: levels and symbols | `level.mark`, `level.schedule`, `section.marker`, `elevation.marker`, `north.arrow`, `slope.arrow` |
| Project data | `project`, `floors`, `beams`, `levels`: kept in the drawing (DXF extension data `AAD_PROJECT`) and restored on open |
| Quantity take-off | `takeoff.start`, `takeoff.linear`, `takeoff.brick`, `takeoff.beams`, `takeoff.columns`, `takeoff.rects`, `takeoff.paint`, `takeoff.ceiling`, `takeoff.floor`, `takeoff.area`, `takeoff.slab`, `takeoff.list`, `takeoff.clear`, `takeoff.export` (CSV), `takeoff.rates`, `takeoff.bill`; opening deductions from blocks |
| Schedules | `schedule`, `openings.std`, `openings.sync`, `openings.table` (door and window schedule drawn as a table) |
| Electrical layout | `electrical.blocks`, `electrical.number`, `electrical.layers`, `electrical.connect`, `electrical.schedule`, `electrical.update` (17 symbol codes, boards and circuits; no load or cable sizing) |
| AQC bridge | `bridge.export` and `bridge.import`: project, floors, beam depths, schedule and measured quantities to and from the AQC estimation program ([hcw-kit-port.md](hcw-kit-port.md)) |
| Xrefs and floor projects | `xref.attach`, `xref.reload`, `xref.detach`, `xref.bind`, `xref.list`; `project.setup`, `project.open`, `floor.list`, `floor.activate`, `floor.set`: a project of floor and layout drawings joined by relative Xrefs, with per-floor visibility, locking and print flags ([projects.md](projects.md)) |
| Sheets and printing | Print and Export to PDF ask for a plot window (two corners, Extents or Display) in model space, `window` for scripts; live viewports; `sheet.titleblock`, `sheet.fields`, `sheet.template.*`, `viewport.list/add/remove`, `floor.viewport`; `plot.batch` and the Plot window ([sheets.md](sheets.md)) |
| Drawing spaces and layer protection | Saved layer-state configurations (`space.*`): visible, frozen and locked per layer, current layer, per-floor scope, preview, status (modified marker), recover; stored in the drawing and applied as one undo step. The engine refuses any change to objects on a locked or frozen layer (model space and layouts), and `layer.current` refuses locked and frozen layers ([ACTIVE_DRAWING_SPACE.md](ACTIVE_DRAWING_SPACE.md)) |
| Context bar and workspaces | Current layer, floor and drawing space selectors in both workspaces; Classic: left toolbars, tabbed right-hand panels pinned; Pro: collapsed panels; each mode keeps its own layout, pin state and toolbars; `floor.current` ([ACTIVE_DRAWING_SPACE.md](ACTIVE_DRAWING_SPACE.md)) |
| Widgets | Architect calculator (`cal`, `ui.toggle.calculator`) and Pomodoro timer (`ui.toggle.pomodoro`) ([widgets.md](widgets.md)) |
| Input forms | Dialogs and command-line prompts for the architecture commands ([input-forms.md](input-forms.md)) |
| Room labels and text styles | The Room command takes the floor from the top bar (no prefix field) and lists the rooms to pick from; Architecture > Rooms and Areas > Room Label Settings saves units, box, text height and font with the drawing (`room.settings`); Format > Text Style opens a text style manager with a picker of installed fonts |
| Interface | Pro and Classic workspaces ([workspaces.md](workspaces.md)), customisable top tool bar, Blocks panel, pin and auto-collapse; command line with prompts, object snaps, polar and ortho tracking, grips, dynamic input, quick properties, light/dark theme toggle (black or white drawing area), |
| WinUI shell | `aad-host` runs a session and paints it with the shared canvas mesh into a Win32 child window. `apps/aad-winui` is an unpackaged WinUI 3 window: menu bar from the engine command registry, command line (prompts, history, Escape cancels), left click and drag selection, object snaps, a rubber-band preview, grips (Enter or Space cycles a hot grip, a typed point applies it, Escape clears it), middle-button pan, right-click Enter, Open/Save/Save As file pickers, a Classic/Pro toggle (Pro hides the side panels), a Dark/Light switch for the window chrome and the drawing area, an in-window PDF preview of the current layout (or another PDF file) rendered by Windows, and dynamic input (the prompt and typed distance or coordinates beside the cursor; Tab inserts the separator; Enter places a locked point). Properties, Layers and Blocks follow a revision-tagged snapshot. Layer on/freeze/lock and current layer, and block insert, go through engine commands. Format > Layers opens a layer manager for the whole table (search, sort, AND filters, color, linetype, lineweight, transparency, plot, description and usage). The layer name is the identity, and undo uses the drawing history. The shell chrome is three quarters of the earlier spacing and type size. A context bar sets the current layer, floor and drawing space. A right-click opens the shortcut menu; Shift or Ctrl with right-click opens the object-snap overrides. Open drawings are tabs under the menu. Ctrl+N, Ctrl+O, Ctrl+S, Ctrl+Shift+S, Ctrl+W, Ctrl+Q, Ctrl+Z, Ctrl+Y, Ctrl+A, Ctrl+X/C/V, Delete, F2 and Ctrl+F11 do what the command registry assigns them, and closing a changed drawing asks whether to save. A double-click edits selected text or enters a layout viewport, and a middle double-click zooms to the extents. Construction lines and rays are drawn on the canvas. The status bar sets lineweight, transparency and quick properties, and opens units, plot scale and the command list (F1). Tools > Drafting Settings, and Osnap Settings, edit polar tracking, object snaps and dynamic input through engine commands. Edit > Quick Select filters the selection. The status Props toggle opens a quick-properties palette for the current selection. Help lists the commands and shows About. Ctrl+Shift+F11 restores the side-column widths. The assistant, AORMS sign-in, docking, calculator and pomodoro stay on the egui window. Classic shows a text tool strip for the draw and modify commands. The status bar has Model and layout tabs, the cursor readout, and Snap, Ortho, Polar, Track and Dyn toggles (F3, F8, F10, F11, F12). Side panels resize with splitters (Pro hides them). A menu command that has a form opens a settings window, then points are picked on the drawing. Space or Enter with an empty command line cycles a hot grip through stretch, move, rotate, scale and mirror. Tab with an empty command line cycles the object snaps under the cursor. `aad` on Windows starts this shell when `Aad.WinUi.exe` is available; `--egui` and `--control` keep the egui window, which still has the assistant and the control channel. wgpu 30 has no SwapChainPanel target, so the drawing is not a XAML panel |
| AORMS connection | Optional sign-in to AORMS (shared login, one session per app), project list, pulling project details and floors into a drawing, drawing list ([aorms.md](aorms.md)). AORMS menu, sign-in/projects dialog and status-bar chip; network calls run off the UI thread |
| Automation | JSON control channel, MCP server, command-line tool, scripts ([control-protocol.md](control-protocol.md), [mcp.md](mcp.md)) |
| Units and annotation | Drawing and display units, plot scale and paper, annotation sizing, collision analysis and text layout ([units-annotation.md](units-annotation.md)) |
| AI agent tool layer | Allow-listed, validated tools for flatten, audit, purge, recover, summary, units, plot configuration and annotation layout ([ai-agent.md](ai-agent.md)) | Spatial knowledge: `spatial.overview/query/nearest/describe` as read-only tools and the `/view` reference ([ai-agent.md](ai-agent.md))
| Project wizard groundwork | Typed versioned project manifest, stable ids, floor elevation derivation, naming patterns, drawing-set and Xref planning with cycle and path checks, read-only preflight, company profiles with logo asset; commands `project.plan`, `project.generate` (creates and verifies the drawings and Xrefs, never overwrites, recoverable), `project.recover`, `company.validate`. The wizard UI, templates, opening-schedule reconciliation and nameplates are not built ([PROJECT_WIZARD.md](PROJECT_WIZARD.md)) |
| Typography | Five font presets (Engineering default) with roles, weights and a deterministic fallback; interface fonts, compact text and headings follow the preset (View > Font Preset, `ui.fonts`); project typography in the manifest and per-role text styles in generated drawings; `fonts.presets`, `fonts.resolve`, `fonts.scan`, `fonts.migrate` (preview and apply to the open drawing or a whole project with backup and report), `fonts.rollback`; the installer can ship fonts from `AAD_FONTS_DIR`. No font files are in the repository, so without them the system font is used ([TYPOGRAPHY.md](TYPOGRAPHY.md)) |
