# Implemented and planned functionality

This page separates what exists (and is tested) from what is only planned. If a feature is not in
the first table it is not implemented. Scope: 2D drafting for architecture and civil work.
Out of scope and removed: 3D modelling and viewing, parametric constraints, and
mechanical-engineering commands (mass properties, ordinate and arc-length dimensions, centre
marks, isometric drafting).

| WinUI shell | `aad-host` runs a session and paints it with the shared canvas mesh into a Win32 child window. `apps/aad-winui` is an unpackaged WinUI 3 window whose icon, Start page and About window use the AAD logo from `assets/app-icon`. The menu, tool strip and status bar use standard WinUI controls and 32px targets; drawn marks stay the icons. The command bar is a rounded composer (muted history, a borderless input, quiet icon buttons): menu bar from the engine command registry, a half-transparent command bar over the drawing (two recent lines, the prompt and input, a history arrow, and Clear history; it does not reserve a layout row, opens at the center, and can be dragged). Space confirms like Enter except at a text prompt or while another text field is focused. A second Space on an empty line repeats the last command, as empty Enter does. Up and Down recall typed lines without running them. Escape cancels. Clear history asks first and only empties the log, left click and drag selection, object snaps, a rubber-band preview, grips (Enter or Space cycles a hot grip, a typed point applies it, Escape clears it), middle-button pan, right-click Enter, Open/Save/Save As file pickers for DXF and DWG, a Classic/Pro toggle (each mode restores its own slot; Pro starts collapsed with an edge strip), a Dark/Light switch for the window chrome and the drawing area (colour 7 is white on the black sheet and black on the white sheet), an in-window PDF preview of the current layout (or another PDF file) rendered by Windows, Dynamic input fields follow the cursor during a point prompt (length and angle, or X and Y), in their own window above the drawing, and stay inside the view. Tab inserts the separator, Enter places a locked point, and the command line remains the text that is submitted. Properties, Layers and Blocks follow a revision-tagged snapshot. The Layer manager tab is that same layer manager. Block insert goes through an engine command. Format > Layers opens a layer manager with a new, delete and set-current tool row, layer states, a search box, a filter list (All, All Used Layers) and one table whose columns are status, name, on, freeze, lock, plot, color, linetype, lineweight, transparency, new-viewport freeze and description. The layer name is the identity, and undo uses the drawing history. Panel text can use a smaller face; the shell, tool strip and command bar stay on the WinUI type ramp. A right-click opens the shortcut menu; Shift or Ctrl with right-click opens the object-snap overrides. Open drawings are WinUI tabs under the menu, with a close mark and a new-drawing button. Ctrl+N, Ctrl+O, Ctrl+S, Ctrl+Shift+S, Ctrl+W, Ctrl+Q, Ctrl+Z, Ctrl+Y, Ctrl+U, Ctrl+A, Ctrl+X/C/V, Delete, F2 and Ctrl+F11 do what the command registry assigns them, and closing a changed drawing asks whether to save. A double-click edits selected text or enters a layout viewport, and a middle double-click zooms to the extents. Construction lines and rays are drawn on the canvas. The status bar sets lineweight, transparency and quick properties, and opens units, plot scale and the command list (F1). Format > Text Style opens a text style manager (list, set current, new, font/height/width/oblique via `style` / `style.list`). File > Plot / Print / Export PDF: in model space the shell starts `plot.window` (window, Extents or Display), then a save picker finishes with `plot`; in a layout a save picker runs `plot` or `exportpdf` directly. File > Page Setup Manager edits a layout's paper, orientation, plot area, scale and lineweights through `pagesetup`. File > Plot Styles opens a plot style manager (`stylesmanager`: list/get/set/new/delete, use table on the current layout, display plot styles). File > Batch Plot plots ticked layouts of the current drawing through `plot.batch` (`sheets`). Format / Dimension > Dimension Style opens a manager for scale, arrow size, text height/gap, decimals, text style and linear units (`dimstyle` / `dimstyle.list`). Format > Linetype, Point Style and Multileader Style, and Architecture > Room Label Settings, open WinUI managers (`linetype` / `ltscale`, `ddptype`, `mleaderstyle`, `room.settings`). Bare typed names for those managers, Units, Layer, Drafting Settings and Quick Select open the same WinUI windows as the menus (JSON `engine.execute` still never opens dialogs). Classic and Pro each keep pin, panel width, collapse and tool-strip visibility (`modeSlots` in shell prefs); the side panel has pin (auto-hide), float, and Window > Reset this workspace (Ctrl+Shift+F11). Pro uses the same edge strip rather than removing the column. Tools > Drafting Settings, and Osnap Settings, edit polar tracking, object snaps and dynamic input through engine commands. Edit > Quick Select filters the selection. The status Props toggle opens a quick-properties palette for the current selection. Help lists the commands and shows About. Ctrl+Shift+F11 resets the current workspace only. The command line sends a `/` request, or a sentence when the model runtime is built in, to the same assistant as the egui window; Allow and Decline answer a tool that would change the drawing. The `assistant` feature of `aad-host` links llama.cpp; this build does not, so those requests report that. AORMS sign-in, the project list, drawings and a status-bar chip call the `aorms.*` commands on the window thread. A loopback JSON channel (the port is on the status bar, `--control`, or `AAD_CONTROL_PORT`) runs `engine.execute`, `engine.commands`, `cmdline.*`, `drawing.inspect`, `ui.menu.list` / `ui.menu.invoke`, `ui.inspect`, `ui.pointer`, `ui.render`, `ui.screenshot` (drawing PNG on WinUI), and `app.open` / `app.save` / `app.quit`; egui widget methods (`ui.click`, `ui.elements`, `ui.drag`, `ui.key`, …) stay on `--egui`. The tool strip is the first column on the left. Beside it, one tabbed column holds Properties, the layer manager and Blocks; dragging the 8 DIP divider (or Left/Right when that grip is focused) changes the width. Layer, floor and space are chosen there. There is no panel on the right and no context bar above the drawing. The side column pin and float buttons control auto-hide and a floating Panels window. Window > Properties / Layers palette / Blocks (and Ctrl+1) opens the matching side tab; the Blocks tab supports Insert, Select references and attribute-definition listing. With nothing selected, Properties edits the current color, layer, linetype and lineweight. A selection edits those values, transparency, linetype scale and the geometry through `properties.set`. The drawing region, menu, tool strip, side panel and status are named for assistive technology; the command prompt and status use live settings; Properties fields are named; the side-panel edge can be resized with Left and Right when focused; command-bar icon buttons are 32px; panel type is at least 12 DIP. With an empty command line, arrow keys move the drafting cursor (Shift for a larger step, Ctrl to pan); Insert picks, places a point, arms a grip or closes a selection window at that cursor; F6 focuses the command line; typed coordinates, Tab snap cycling and Enter/Space grip modes remain the primary keyboard drafting path. Menu shortcut chords are real KeyboardAccelerator bindings parsed from the engine registry (the same strings shown on the menu), and the shell key map is built from those bindings. Settings and tool windows (forms, units, drafting settings, layer manager, quick select, quick properties, calculator, Pomodoro, tool bar, AORMS, save prompt, About, command list, PDF preview and the shortcut menu) name their fields, use full-opacity secondary text where needed, announce status politely where it changes, and keep action targets at least 32 DIP. The calculator runs `cal`. The Pomodoro window uses the same 5-to-60-minute countdown as the engine state machine. The tool strip can be chosen, and the chrome can use a system face (Engineering, Editorial, Multilingual, Compact, Drafting utility) with no font files. A Start tab covers the drawing with New and Open. The world-coordinate icon is drawn on the canvas; a click offers World or Hide. Window toggles hide the menu bar, tool strip, file tabs, status bar or command line on their own (Ctrl+9 is the command line, Alt shows the menu bar again, Ctrl+Shift+F11 resets the current workspace). Classic shows the tool strip of drawn command icons on the left. It stays open when Properties collapses; the name is the tooltip. The status bar has Model and layout tabs (each with a sheet mark), the cursor readout, and drawn toggles for snap, ortho, polar, tracking, dynamic input, lineweight, transparency and quick properties (F3, F8, F10, F11, F12). The layer manager uses the same marks for on, freeze, lock, plot and its tool row. Side panels resize with splitters (Pro hides them). A menu command that has a form opens a settings window, then points are picked on the drawing. Space or Enter with an empty command line cycles a hot grip through stretch, move, rotate, scale and mirror. Tab with an empty command line cycles the object snaps under the cursor. `aad` on Windows (default build, no eframe) starts this shell when `Aad.WinUi.exe` is available, forwarding `--sample`, `--control` and drawing paths; rebuild with `--features egui` and pass `--egui` for the optional egui window (assistant UI and egui-only control methods). The x64 Windows package stages `Aad.WinUi.exe`, `aad_host.dll` and the self-contained Windows App SDK beside `aad.exe`. wgpu 30 has no SwapChainPanel target, so the drawing is not a XAML panel |
