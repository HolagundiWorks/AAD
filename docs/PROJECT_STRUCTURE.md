# Project structure

Where things are. For what the crates do and how they fit together read
[ARCHITECTURE.md](ARCHITECTURE.md). Only significant directories are listed. Counts are tracked
files on `main` on 2026-10-19.

## Top level

| Path | Purpose |
|---|---|
| `Cargo.toml`, `Cargo.lock` | Workspace definition (members `crates/*`, `apps/*`, `xtask`), shared version, profiles. The lockfile is committed and `cargo build --locked` is used for packaging |
| `crates/` | The 17 library crates |
| `apps/` | `aad` (desktop app, shipped as `o-draft.exe`), `aad-cli` (command-line tool, MCP), `aad-web` (WASM build, compile-checked only), `aad-winui` (C# WinUI shell, `ODraft.WinUi.exe`; excluded from the Cargo workspace) |
| `xtask/` | Repository tasks: `cargo xtask ci`, `layers`, `assets`, `wasm`, `parity`, `version`, `logo`, `stats`, `licenses`. `xtask/data/menu-catalog.txt` is the menu-name list used by `parity` |
| `docs/` | Documentation (index in [README.md](../README.md)); maintenance rules in [documentation-policy.md](documentation-policy.md) |
| `packaging/` | Installer and release scripts per platform (`windows/`, `macos/`, `linux/`, `web/`) |
| `assets/app-icon/` | The O-Draft logo as SVG and generated icons (PNG sizes, `.ico`, `.icns`, Linux hicolor). Generated by `cargo xtask logo`, committed |
| `examples/apartment.dxf` | Sample drawing used by tests and the mutation robustness test |
| `tools/quality/` | `baseline.ps1` (build and test timings report), `synthetic.rs` (deterministic benchmark drawing shared by the bench files) |
| `.github/workflows/` | CI (`cad-ci.yml`, `cad-nightly.yml`), release (`release.yml`), packaging lint |
| `.cargo/config.toml` | The `cargo xtask` alias |
| `ATTRIBUTION.md`, `NOTICE`, `LICENSE-*`, `THIRD_PARTY_LICENSES.md` | Licences, dependency licence inventory (`cargo xtask licenses`) and asset sources. Not to be removed |
| `CLAUDE.md`, `CONTRIBUTING.md` | Rules for developers and coding agents |
| `clippy.toml`, `rustfmt.toml` | Lint and format configuration |

Generated and ignored (see `.gitignore`): `target/` (Cargo build output), `dist/` (release files),
`log/`, `temp/`, `plan/`, `plans/`.

## Entry points

| Binary | File |
|---|---|
| `aad` (shipped as `o-draft.exe`) | `apps/aad/src/main.rs` (the DWG worker mode is handled first in `main`). Non-Windows always links egui/eframe |
| `aad-vdb` | `crates/vdb` — ShilpiDB-backed `.vdb` file (format v2) + `VdbClient`; engine commands `vdb.export` / `import` / `info` / `query` / `connect` / `disconnect` / `push` / `pull` / `sidecar` / `status` |
| `aad-param` | `crates/param` — parametric graph library; engine commands `param.*` ([parametric.md](parametric.md)) |
| `ODraft.WinUi.exe` | `apps/aad-winui` (C#, not a Cargo member; assembly `ODraft.WinUi`, namespace `Aad.WinUi`) |
| `aad-cli` | `apps/aad-cli/src/main.rs` |
| `aad-web` | `apps/aad-web/src/main.rs` (WASM) |
| `xtask` | `xtask/src/main.rs` |

## Resources loaded at run time

None are read from the install folder. Icons are drawn in code; hatch patterns, linetypes and the
drafting font are compiled in; the interface is English only (strings are in the code). System fonts are
read from the operating system if present. The optional
language model file is looked up in `AAD_MODEL`, the settings folder's `models`, and a `models` folder beside the program (`crates/llm/src/files.rs`) and is never
committed.

## Tests and fixtures

See [TESTING.md](TESTING.md). Fixtures that are files live next to their tests, for example
`apps/aad-cli/tests/fixtures/dwg/` (with a README stating how each was made).

## Names

The product is **O-Draft**, the drafting app of OSAS (the Open Source Architecture Suite), beside O-Studio and O-CoreOp. It was called AAD (Accelerated Architecture Drafting). Only what a person reads was renamed: window titles, About, menus, the installer, the logo and the documents. Identifiers that other things read keep their old names, so nothing breaks:

| Kept | Why |
|---|---|
| Crates and libraries `aad-*`, `aad_host.dll`, the Cargo binary names `aad` and `aad-cli`, the C# namespace `Aad.WinUi` | Other crates import them. The Windows package renames the two programs it ships: `aad` becomes `o-draft.exe` and the WinUI shell is `ODraft.WinUi.exe`; the OSAS launcher looks for `o-draft.exe` first and `aad.exe` as a fallback for old installs |
| Command ids, the command-line grammar, MCP tool names (`serverInfo.name` is `aad`), control-channel methods | Scripts and agents call them |
| File formats: `AAD_PROJECT` extension data in DXF, `.vdb`, the `hcw-aqc-bridge` file (`source.app` is `AAD`) | Existing drawings and AQC import must keep working |
| The AORMS session name `aad` and credential `AORMS/Connect/aad`, the application id `io.github.holagundiworks.aad` | The portal and the other apps read them |
| `%APPDATA%\AAD`, `%LOCALAPPDATA%\AAD`, `AAD_*` environment variables, the `AAD Stroke` font name, `AAD-MANUAL`, `AAD-TITLEBLOCK` | Users' settings and saved drawings |
| The WiX UpgradeCode and the `AAD.Drawing` file association | An installed copy must still upgrade |
| The repository name | Links and clones |

The Windows programs ship as `o-draft.exe` (the `aad` binary, renamed by `packaging/windows/package.ps1`) and `ODraft.WinUi.exe`; `aad-cli.exe` keeps its name. The OSAS launcher finds both `o-draft.exe` and the older `aad.exe`. The installer and its files are named `o-draft-<version>-windows-<arch>`. The logo is the OSAS suite mark in O-Draft's black, drawn by `cargo xtask logo`. The accent colour is black (`#1B1C20`) in the light palette and a light neutral (`#F6F5F1`) in the dark palette, where black would not show; the two palettes are `theme::Tokens` in `crates/ui-egui/src/theme.rs`, and the WinUI shell sets the same values in `apps/aad-winui/App.xaml`.
